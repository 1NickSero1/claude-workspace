[2026-07-22] Bug real encontrado al probar el chat de verdad: no era la API key
- El usuario probo el chat de Maquillaje y Skincare con la key placeholder de
  secreto.py y le aparecio "Sistema: Ocurrio un error inesperado" (el catch-all
  generico de skills/base.py, no el mensaje especifico de "falta la API key").
  Eso encendio la alarma - un error de key invalida deberia caer en el except
  anthropic.AuthenticationError especifico, no en el generico.
- Diagnostico: skills/base.py mandaba output_config=OUTPUT_CONFIG a
  cliente.messages.create(), pero el paquete "anthropic" real de PyPI que
  soporta ese parametro requiere Python >=3.9. Este proyecto esta fijado a
  Python 3.8 a proposito (compatibilidad con Windows 7). La ultima version de
  anthropic instalable en Python 3.8 es 0.72.0 (confirmado contra el indice de
  PyPI), y esa version no tiene output_config en su firma - mandarlo tira un
  TypeError local ("unexpected keyword argument") antes de llegar siquiera a
  la red, y ese TypeError generico es justo lo que el usuario vio.
- Arreglado: se saco output_config de la llamada en skills/base.py y se borro
  la constante OUTPUT_CONFIG de config.py (dejando un comentario explicando
  por que no se puede usar mientras el proyecto siga en Python 3.8). Sin
  output_config no hay control de "effort" - el chat corre con el effort por
  defecto del modelo, no en modo bajo. LIMITE_TOKENS_DIARIOS y
  LIMITE_MENSAJES_SESION siguen siendo el control de costo real.
- Verificado reproduciendo la llamada real a la API con la key placeholder:
  antes del fix tiraba TypeError de inmediato (sin red); despues del fix llega
  hasta el servidor y devuelve anthropic.AuthenticationError (401, invalid
  x-api-key) - exactamente el error que skills/base.py ya sabe manejar con el
  mensaje "Falta configurar la API key correctamente". Con la key real puesta
  en secreto.py, el chat deberia funcionar de punta a punta.
