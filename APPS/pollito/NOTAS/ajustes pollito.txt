  Psicologia). skills/memoria_psicologia.py se generalizo a skills/memoria.py

  Las 5 skills ahora dejan explicito en el prompt que la usuaria es Sofi y
  que no se debe guardar como si fuera de ella informacion de una
  conversacion que no parezca ser con ella (el usuario aviso que el tambien

- Confirmado con `python -c "import main; import skills.*"` (Python 3.8) que

- Chat rediseñado con burbujas (VentanaChat en skills/base.py) con el nombre
  del remitente arriba de cada una ("Sofi" en las propias, el nombre de la
  skill en las de respuesta) - verificado en vivo con mensajes de prueba
  (sin llamar a la API real).
- BUG REAL encontrado probando el chat con la key placeholder: aparecia
  "Sistema: Ocurrio un error inesperado" (el catch-all generico) en vez del
  mensaje especifico de API key invalida. Causa real: skills/base.py mandaba
  output_config=OUTPUT_CONFIG a messages.create(), pero ese parametro
  requiere una version de "anthropic" que necesita Python >=3.9 - la ultima
  version instalable en Python 3.8 (0.72.0, el que usa este proyecto) no lo
  tiene, y tiraba un TypeError local antes de llegar a la red. Se saco
  output_config de la llamada y se borro la constante de config.py (con un
  comentario explicando la limitacion). Sin esto no hay control de "effort"
  (queda en el default del modelo) - el control de costo real sigue siendo
  LIMITE_TOKENS_DIARIOS y LIMITE_MENSAJES_SESION. Verificado reproduciendo la
  llamada real: ahora llega hasta el servidor y devuelve
  AuthenticationError (401) en vez del TypeError - confirma que con la key
  real puesta, el chat deberia funcionar.
